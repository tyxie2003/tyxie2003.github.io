### MacOS directory

It comes from Unix. Under `/` you see directories, partly from unix (they kept the names for capatibility), partly added by MacOS (with capital letters).

###### (From Unix)

•  `bin`  — essential command-line programs (ls ,  cp ,  cat)
•  `cores`  — where crash "core dump" files would go
•  `dev ` — the device folder (disks)
•  `home`  (symlink →  `/System/Volumes/Data/home` ) — legacy Unix convention pointing to user home folders; macOS actually uses  /Users  day-to-day
•  `opt` — optional/third-party software installs (Homebrew)
•  `private`  — where symlinks (etc, tmp, var) points to. Grouping "system-internal, frequently-changing" data. They usually has a alias outside `private`
	•  `var` (symlink →  `private/var` ) — "variable" data: logs, caches, spool files that change frequently 
	•  `etc`  (symlink →  `/private/etc` ) — et cetera (system configuration files)
	•  `tmp`  (symlink →  `private/tmp` ) — temporary scratch files, cleared periodically/on reboot
•  `sbin`  — system administration binaries (commands typically needing admin rights, like  reboot ,  fsck )
•  `usr` — more Unix things ("Unix System Resources")

###### (Added by MacOS)

•  `Applications ` — shared apps folder
•  `Library ` — system-wide support files (fonts, system preferences, shared frameworks)
•  `System`  — protected macOS ("Macintosh HD" later seen in disk3s1)
•  `Users`  — contains every user account's home folder ( Users/tyxie  = your  ~ )
•  `Volumes`  — where other mounted disks (external drives, disk images, network shares) appear as folders

#### ` /dev`  

each entry inside it represents a device your computer can talk to (disks, USB drives, printers, etc.). Treat hardware "as if it were a file".

With `diskutil list`, I can see the structure of disk. `s` is for slides.

- Disk0: 0 overall storage. 1 for boot security. 3 for recovery of system. 2 all data (synthesized to be disk3)
- Disk3: 0 overall storage, 1 MacOS. 2 MacOS snapshot, don't occupy more space. 3 boot-related 4 recovery 6 virtual memory swap space macOS uses when RAM is full. 5 data 

Looks like many of them are security measurements. Remember the computer itself is just bunch of hardware, it's the system installed on it make it run. If the system is broken at some point, we need these measurement such as recovery mode. They should be outside the "system". 

#### `/Users`

Sometimes I got confused why there's `Application`, `Library` in both `~` and `/`? The answer is, `/` is the "root" directory for the computer, supposed to be maintained by sudo; `~` is the `Users/username` directory, controled by you, a user. 

### What can be freed? 

1. Reboot

The first thing I learned is do reboot once in a while. That freed almost **30GB**. I see it deletes the caches under `/tmp`, maybe also caches from other places. 

2. Check space

Beyond that, like I said, I want to clean every corner so that the pop-out messages of no storage never appear again to bother me. By `du -sh`, I found 

- `usr` 9.8G (`local/texlive`)
- `opt` 10G (Homebrew)
- `Users` 64G
- `Library` 35G
- `Applications` 22G

`System` yields 200G I guess it's the total space, not useful for reference. You can also use Finder or Settings of Mac to see the storage, but it has different calculating method, thus yielding different numbers. Since anyway the Finder doesn't show all the folders (some are hidden), we just stick to `du -sh` in terminal.

3. Mole

When searching up for how to clean up my homebrew, I saw a blog leading to a some program called [Mole](https://mole.fit), which exactly do the storage-freeing job. The [open-source version](https://github.com/tw93/Mole) is on Github. It's written by [some engineer](https://tw93.fun/en/) in 2 days to free up his own mac, but since they know computer better, it does save our time. 

To install, just `brew install mole`. Then type `mo --help` for what it can do. Try with options with `--dry-run` to make sure it's safe. You can also add `--white-list` for what you don't what it to touch. Also see [Video](https://www.youtube.com/watch?v=UEe9-w4CcQ0) for tutorial (in Chinese)

Anyway, I used it to cleanup. I suppose it just searches for all folders in `~` with "Caches" or "Log" and delete things in it. Caches means things temporarily installed. Log means the history of operation, might be useful for debugging or developers. They can be regenerated and won't affect normal usage. I whitelisted my VSCode and Safari Caches but not sure if necessary. It frees up **7GB**. 

It can also uninstall apps. However, that is also easily accessible in storage settings in Mac itself.

4. Homebrew

[Homebrew](https://brew.sh) is package managing thing, just like `pip`, `conda`. So Claude told me: 

- `brew cleanup` deletes old versions of formulas/casks you've upgraded past, plus cached downloads. Add `-n` first (`brew cleanup -n`) to preview what would be removed without deleting anything,

- `brew autoremove` removes formulas that were only installed as dependencies of something else you've since uninstalled. Run `brew leaves` first to see what you have installed directly (as opposed to as a dependency) — anything not in that list but still installed is a candidate for cleanup.

I didn't try autoremove, since I am a bit PTSD with the WSL-deletion accident. What I did is just `brew uninstall --cask mactex-no-gui xquartz`, because I found texlive in `/usr` and my copilot told me it's never used, and that xquartz never functioned satisfactory and I turned to python ploting. `mactex-no-gui` itself took away 17GB.
